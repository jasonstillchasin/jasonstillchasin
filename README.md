Most of what I build exists to prove me wrong before anyone else can.

My research uses pre-registered tests and explicit statistical gates, so a good story cannot survive on vibes alone—whether I am testing an index effect, a trading strategy, or an LLM agent’s factor selections. When something clears the bar, I write it up. When it does not, I write that up too.

Outside research, I build software, from a peer-tutoring platform to my own AI assistant stack, and compete in mathematics olympiads, where learning to be wrong quickly is also a useful skill.

---

### 🔬 quant research

- **RECON**, an event study on S&P/ASX 200 index reconstitution with a pre-registered gate. Killed at the power analysis stage instead of forced into a false positive. Now a methods paper.
- **Project-Drift**, a backtesting platform built to falsify strategies before believing them. Five candidates tested, five rejected. [Paper on SSRN](https://papers.ssrn.com/abstract=7104418).
- **NULLIUS**, a reality check for LLM-driven factor selection. The agent clears a 200-draw bootstrapped null decisively, but is statistically indistinguishable from budget-matched random search once publication selection and multiplicity are accounted for. [Paper on SSRN](https://papers.ssrn.com/abstract=7190318).
- **Project BOB**, a LightGBM LambdaRank equity ranking model, written up as a working paper.
- **ASX Wheel Options Trader**, an options system on the IBKR TWS API with Kelly sizing and regime detection.

---

### 💻 software

- **Radian**, a full-stack peer-tutoring booking platform for my school. React/Vite, Vercel serverless, Redis, Resend.
- **Jarvis**, a personal AI assistant stack on n8n, FastAPI and Ollama.
- **TokenLens**, a cost analyser for Claude Code usage.
